# Meta-Cognitive Context Loom Visualizer

A Pluriversal React environment for rendering Epistemic Schemas and maintaining Golden Scar Superpositions between human intuition and AI formalism.

## Purpose

The Meta-Cognitive Context Loom Visualizer is a sophisticated React application designed to parse and visually render complex epistemic schemas and domain lexicons. Rather than acting as a simple data presentation layer, it enforces a dialectic architectural mandate. It deliberately exposes and suspends the tension between rigid, algorithmic structures generated by AI (formalism) and the nuanced, practical wisdom provided by human operators (phronesis). This application explicitly prohibits automated systems from resolving deep contradictions, forcing a collaborative "Golden Scar Superposition" to maintain architectural integrity.

## Architectural Synergies (AI x Human)

This visualizer does not merely render data; it enforces an architectural mandate where neither the AI nor the Human can resolve complex tension alone:
- **AI Provision:** Maintains the multi-dimensional structure (Causal Validation Matrix, DRP-LEXICON-992). Generates rigid structural constraints and maps the negative space of known failure modes.
- **Human Provision:** Injects Phronesis (practical wisdom) via the **Paraconsistent Loom**, weighting contradictions without collapsing them. Navigates the positive space left open by the AI's boundaries.

## The Agent Inversion Strategy

The repository implements an **Epistemic Escrow Circuit Breaker**. Instead of the AI attempting to hallucinate a resolution when contradictions peak, the system physically halts execution when the Contradiction/Fracture/Divergence Index (CFDI) exceeds 0.15. It explicitly requires the human to apply a topological deformer to resolve the state, ensuring that agentic autonomy is derived from its rigorous ability to refuse invalid states.

## Developer Guide

### Prerequisites

- **Node.js:** version 18+
- **NPM:** standard node package manager

### Setup and Installation

1. Clone the repository and navigate to the root directory.
2. Install all necessary dependencies by running:
   `npm install`

### Running the Application

To start the local development server (using Vite), run:

`npm run dev`

The application will typically start on `http://localhost:3000` (or another port if 3000 is occupied). It includes hot module replacement for a seamless development experience.

### Testing

The project uses `vitest` and `@testing-library/react` to enforce strict behavioral correctness. It follows Test-Driven Development (TDD) principles.

Execute the strictly pinned Test Suite (Vitest) by running:

`npm run test`
(Alternatively, you can run `npx vitest run`)

### Code Structure

The application source code is contained entirely within the `src/` directory to adhere to the strict **Root Hygiene Enforced** rule (root is reserved for configuration only):

- **`src/components/`**: Core UI components.
  - `EpistemicEscrowBreaker.tsx`: The circuit breaker that halts execution based on CFDI metrics.
  - `ParaconsistentLoom.tsx`: The dialectical input mechanism for balancing AI formalism and Human Phronesis.
  - `JsonViewer.tsx`: A recursive component to beautifully render the epistemic schema and JSON objects.
- **`src/data/`**: Contains static domain data, notably `lexicon_data.json`.
- **`src/App.tsx`**: The main container and global state manager.
- **`src/index.tsx`**: The React entry point.

### Contribution Guidelines

1. **Test-Driven Development (TDD):** Every code addition must be accompanied by appropriate test cases ensuring Red-Green-Refactor cycles.
2. **Mandatory Documentation:** All public methods, components, and properties must contain accurate JSDoc strings.
3. **Strict Dependencies:** Package versions are strictly pinned (no `^`, `~`, `latest`, or `*`). Do not arbitrarily update dependencies unless explicitly required for stability.
4. **Agentic Code Constraints:** Do not alter the core paraconsistent behavior. Do not circumvent the CFDI constraints.

*Note: Root hygiene is strictly enforced. No application data or scripts exist in the root directory.*
